Who, where,
on which port.

Grant access to a device or a group of servers. The panel builds the headscale policy and restores the previous version if the new one is rejected. Personal devices stay isolated from one another.

The right destination.
The right gateway.

Choose which nodes reach a domain or subnet through a particular server. When the domain's address changes, the panel updates the route. You also choose the internet exit gateways available to each device.

Services keep
their names.

Connect a service name to a node inside the network. If the node reconnects, the record follows its new address. Public DNS stays as it was, and internal names can have their own certificates.

One node.
The full picture.

Roles, access, subnets and gateways sit alongside the agent's state. Select a server and work with its details while keeping the other nodes in view.

Network settings,
within reach.

The address range, Tailscale client version, local binary mirror and API keys are available in the panel. Settings that affect the network come with explanations of what they change.

Your sign-in.
Your control.

Enable TOTP two-factor authentication and choose how long to trust your own devices. Review and revoke remembered devices from the panel.

The real interface with demo data. Node names and addresses shown in the screenshots are fictional.

Everyday operations

Less manual work
on every node.

The panel holds the desired network state. The agent applies it on Linux nodes and reports what it actually applied.

Explore the documentation ↗
01

A signed agent

The agent verifies an update's signature before installing it. Routes, gateway egress and client settings are applied on the node itself.

02

TLS for internal names

The private key is generated on the node and stays there. The panel signs the certificate with its own authority; the agent handles renewal.

03

2FA and trusted devices

A second factor, remembered-device controls, sign-in attempt limits and an administrator audit log.

04

Backups and monitoring

Snapshots of panel settings and the headscale database, uptime history, Telegram or webhook alerts. Including when the panel itself has a problem.

Get started

Run it on
your own server.

The installer brings up NodeRoost, headscale and a TLS reverse proxy with Docker Compose.

  • An Ubuntu or Debian server with sudo access
  • Two domains: one for the panel, one for the control server
  • Your public IP address to allow access to the panel
Full installation guide ↗Security recommendations ↗
Install NodeRoost
curl -fsSL https://raw.githubusercontent.com/mihsergeev/NodeRoost/main/ops/install.sh \
  | sudo bash -s -- \
      --panel-domain panel.example.com \
      --hs-domain hs.example.com \
      --allow-ips "203.0.113.10"

Replace the domains and example IP with your own. The installer generates secrets and prints your sign-in details when it finishes.
