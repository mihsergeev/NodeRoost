Your own panel for headscale

NodeRoost runs the tailnet on your own control server: who may reach whom, which node the traffic goes through, and where the way out to the internet is open. No hand-editing of HuJSON.

View on GitHub How it works

Open source, BSD-3-Clause. Runs in Docker next to headscale.

What it does

headscale runs the tailnet, but talks to you in HuJSON policy. NodeRoost restates it in the terms you already think in: servers, devices, grants, routes.

Servers and devices

Nodes split into servers (things you connect to) and personal devices. Devices are isolated from each other and are never a rule’s target — enforced in the policy engine, not in the UI.

Grants, not an ACL file

A rule is «who → where → on which port», granted by clicking, to several at once if you like. The panel assembles the HuJSON itself.

Roles

A role is a group of servers (a headscale tag). Grant access to the role, and adding a server to it needs no rule changes.

Routing

Directions: «these nodes reach that address through this node». The panel resolves the name itself and updates the route if the site moves.

Internet egress through gateways

Mark a server as a gateway and pick which devices may use it. In the Tailscale tray the user sees only the exits you allowed — the choice is theirs, the set is yours.

Agent on the node

Routes and exit are set in the panel and applied by the node itself: headscale has no panel-to-node channel, so this one is ours.

Backups and restore

A consistent snapshot of the headscale database and panel settings, a self-test of the archive, scheduled backups and a rehearsed restore.

Monitoring and alerts

Uptime history, Telegram or webhook alerts when a server drops or a key is about to expire, plus an independent host watchdog for when the panel itself goes quiet.

How it works

The panel reaches headscale over the internal network; only the node-facing side of the control server is exposed.

Bring it up

Docker Compose: headscale, the panel and Postgres. A reverse proxy terminates TLS and keeps the panel behind an allow-list.

Join the nodes

The panel issues a one-time key and a ready command for the OS at hand — Linux, Windows, macOS, Android.

Hand out access

Tick who goes where. The policy is rebuilt and pushed to headscale automatically, and rolled back if it is refused.

curl -fsSL https://your-control-server/agent/<token>/setup | sh

Straight talk about security

The panel runs a VPN network, so the invariants live in the code rather than the interface — a rule can arrive through the API too.

  • Devices cannot reach each other. A device cannot become a rule’s target by picking it from a list or by typing its address by hand.
  • A node cannot promote itself. A node’s class and its tags follow only what the administrator approved.
  • Sign-in: JWT and TOTP, attempt limits, an audit log; the panel refuses to start with a weak secret or the default password.
  • Every release builds from a hash-verified dependency lock, with base images pinned by digest.
